# YOLO 与 K0 契约

## 最终模型只有两个类别

本项目使用一个目标检测模型，不是两个模型：

```yaml
names:
  0: empty_hole
  1: tube_cap
```

- 空槽：只标一个 `empty_hole` 框，框中心对准孔的几何中心。
- 有管槽：只标一个 `tube_cap` 框，框中心对准盖顶中心。
- 同一个槽不能同时出现两个类别。
- 每张完整俯视机架图必须对应 12 个标注；机架、外框、K0 和试管管身都不是 YOLO 类别。

一次运行画面只允许出现当前要操作的一个完整机架。若同时把两个机架或其他相似孔阵列放进视野，严格的 12 框检查会拒绝该帧。

运行时也执行同一严格契约：必须恰好输出 12 个框，类别只能是上述两个。当前版本不会对缺失框补位，也不会在多框时做猜测，因为错误补位会直接变成错误抓取。

## 数据采集和划分

最终训练集应覆盖真实部署条件：

- D435 实际观测高度、接近 1280×720 的画面构图和竖直视角；
- rack_1 红 K0、rack_2 绿 K0，以及不同占用组合；
- 全空、全满、单管、边角有管和随机混合状态；
- 实验室正常灯光、偏亮/偏暗、轻微曝光变化和允许范围内的机架小偏移；
- 实际使用的不同盖子颜色、反光和背景。

连续视频相邻帧不能随机拆到 train/val/test 三边，否则指标会虚高。按拍摄批次、日期或完整视频分组划分，至少把一个独立拍摄批次只留给最终测试。

标框的一致性比框得很大更重要。系统用框中心取深度和 XY；框中心偏到盖沿、孔壁或背景，会在 mAP 看起来正常时仍产生三维误差。

## 部署步骤

训练完成后，将最终权重复制为：

```text
models/tube_slots.pt
```

不要覆盖代码中的类别名称来迁就训练错误；先确认权重自身的名称：

```powershell
python -c "from ultralytics import YOLO; print(YOLO('models/tube_slots.pt').names)"
```

输出必须严格等于：

```text
{0: 'empty_hole', 1: 'tube_cap'}
```

随后执行：

```powershell
python -m tube_grabber doctor
python -m tube_grabber scan --rack rack_1
python -m tube_grabber scan --rack rack_2
```

默认推理设备为 `cpu`，适合未确认有 NVIDIA CUDA 的小型 NUC。只有确认 CUDA、PyTorch 与驱动均正常后，才在 `config/app.yaml` 改 `vision.device`。

## 不只看 mAP

选择最终模型时至少记录以下系统指标：

1. **exact-12 rate**：完整机架图中恰好得到 12 个正确目标的比例。
2. **完整状态准确率**：一张图 12 个槽位全部判对才算成功。
3. **槽位编号准确率**：结合 K0 后 `r1c1…r2c6` 是否全部对应正确。
4. **中心点误差**：框中心到真实孔/盖中心的像素误差及换算后的 XY 误差。
5. **三维重复性**：固定场景重复扫描得到的 base 坐标标准差。
6. **最终任务成功率**：抓取、搬运、放置完整成功，而不只是检测成功。

置信度默认 `0.45`、NMS IoU 默认 `0.45`。调阈值应在独立测试集和保存的真机图上比较 exact-12 rate；不要单纯降低阈值以掩盖漏检，因为多框同样会被安全拒绝。

## 5 mm × 5 mm K0

K0 不参与 YOLO 训练，由 HSV 单独检测：

- `rack_1` 使用红色，`rack_2` 使用绿色；
- 色块实际尺寸均为 5 mm × 5 mm；
- 色块放在机架外框、靠近要定义为 `r1c1` 的角；
- 色块不能落入孔或盖的 YOLO 框，画面中像素面积应稳定大于 `minimum_area_px`；
- 材料尽量哑光，避免高光把饱和度和值压出阈值范围。

程序会先拟合网格，只接受位于某个网格角外侧、近方形且唯一的颜色候选作为 K0。零个或多个候选都会拒绝，避免同色物体把编号镜像。K0 决定行列正方向，编号规则始终是“先行后列”。若红/绿范围或光照变化，需要调整 `markers` 下的 HSV 参数并重新对两个 rack 做重复扫描，不需要重训 YOLO。

## 架面 Z 与 5 mm 抓取深度

盖顶三维点来自 D435 深度。默认要求所有盖顶 Z 相对中位数不超过 2 mm；存在架面标定时，每个盖顶还必须直接落在“标定架面 + 实测突出高度”的 2 mm 范围内。然后按以下规则得到架面 Z：

1. 图中存在 `tube_cap`：盖顶 Z 中位数减去 `cap_top_above_rack_mm`，得到实测架面；
2. 已有 `fallback_plane_z_mm`：实测架面与标定相差不得超过 `maximum_plane_calibration_error_mm`，最终使用稳定的标定架面；
3. 图中完全无管：必须使用对应 rack 的 `fallback_plane_z_mm`；
4. 无盖且无标定：拒绝扫描，不生成放置坐标。

`cap_top_above_rack_mm` 必须用最终试管、最终机架实际测量，当前配置值不能因为“看起来差不多”直接确认。抓取点固定为盖顶下方 5 mm；放置高度也用同一 5 mm 和可选的 `seating_adjust_mm` 计算。

一种无需额外程序的开机架面校准方法是：在机架内放入至少一支完全坐实的标准试管，固定底盘和观测位，连续扫描多次，取输出 `plane_z` 的中位数写入该 rack 的 `fallback_plane_z_mm`，然后用全空机架复扫验证。两个物理架分别标定，底盘或机架位置变化后重新做。真实 `transfer` 会强制要求当前 rack 已填写这个值，不能只依赖单帧深度。
