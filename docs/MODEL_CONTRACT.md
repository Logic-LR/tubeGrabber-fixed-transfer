# 模型契约

## 试管盖 detection

权重：`models/cap.pt`

```yaml
names:
  0: tube_cap
```

每根已就位试管只标一个盖框，框中心应稳定落在盖顶可取深度的位置。不要标空孔、
架面或槽位。验证集需要覆盖不同槽位、占用组合、盖色、反光和允许范围内的曝光变化。

## 架面 Pose

权重：`models/rack_pose.pt`，类别固定为 `0: rack_surface`，关键点固定为 8×3：

```text
k0, k1, k2, k3, screw_k0, screw_k1, screw_k2, screw_k3
```

K0～K3 是同一物理架的顺时针角点编号，不是图片方向。`screw_kN` 是靠近对应
KN 的螺丝孔中心。`screw_k0` 旁必须在采集前贴好永久小红圆点。完整标注细则见
`training/RACK_POSE_CONTRACT.md`。

## 运行时契约

- real 模式固定使用 `CUDA:0`；CUDA 不可用时失败，不回退 CPU。
- Pose 必须恰好返回一个架面、8 点及每点置信度。
- 两个模型仅首次推理时加载，之后复用同一实例。
- 模型类别名不一致、关键点数量/顺序不一致时立即失败。
- 架面模型离线验收默认要求 pose mAP50 ≥0.95、mAP50-95 ≥0.75；最终门限可根据独立测试集调整，但不得只用训练集结果。
- 现场还必须通过连续扫描统计：关键点最大抖动、槽位三维抖动、盖顶三维抖动和整链延迟。

架面模型当前尚未制作。没有真实权重和现场数据时，离线单元测试只能证明算法与
门禁逻辑正确，不能宣称已经达到真实识别精度或帧率。
