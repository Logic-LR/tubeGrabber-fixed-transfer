# 模型契约

## 试管盖 detection

权重：`models/cap.pt`

```yaml
names:
  0: item
```

每根已就位试管只标一个盖框，框中心应稳定落在盖顶可取深度的位置。不要标空孔、
架面或槽位。验证集需要覆盖不同槽位、占用组合、盖色、反光和允许范围内的曝光变化。

程序适配层将其固定映射为内部语义 `tube_cap`。

## 架面四螺丝 detection

权重：`models/screw.pt`，类别固定为 `0: item`。每个架面必须稳定检出恰好四颗
角螺丝；运行时只取每个框的中心点。额外白色 marker 不属于 YOLO 类别，由 HSV
高亮低饱和连通域检测，在遮掉四个螺丝框后用于确认物理 K0。

四个无身份中心先绕质心排序；marker 最近角为 K0；K0 的长边邻点为 K1，随后得到
K2、K3。marker 缺失、候选歧义、螺丝数量不是四个或架面几何不合理时均失败。

## 运行时契约

- real 模式固定使用 `CUDA:0`；CUDA 不可用时失败，不回退 CPU。
- screw 必须恰好返回 4 个框，并通过白色 marker 唯一确定 K0。
- 两个模型仅首次推理时加载，之后复用同一实例。
- 模型类别名不一致、关键点数量/顺序不一致时立即失败。
- 架面模型应在独立测试集和真实连续视频上验收，不得只看训练集指标。
- 现场还必须通过连续扫描统计：关键点最大抖动、槽位三维抖动、盖顶三维抖动和整链延迟。

离线单元测试只能证明排序、marker 定向、几何和门禁逻辑正确；真实识别精度和
帧率必须用 `tools/test_yolo_stream.py` 在部署机现场确认。
